# Задачи второго бэкенд-разработчика

Каждая карточка рассчитана на отдельный PR. Первым можно выдать **BE-01**, если приоритетом стал расчёт, или **BE-02**, если фронтенду нужен экран «Мои лендинги». Для обеих задач уже достаточно информации. Имена новых маршрутов ниже — предлагаемые контракты для согласования с фронтендом до реализации.

| ID | Что получит пользователь | Зависимость |
| --- | --- | --- |
| BE-01 | Расчёт стоимости пакета занятий | Готова к выдаче, [постановка и примеры](pricing-task.md) |
| BE-02 | Список своих лендингов | Готова к выдаче |
| BE-03 | Предпросмотр черновика для выбранной аудитории | Готова к выдаче |
| BE-04 | Сохранение настроек блока калькулятора | После BE-01 |
| BE-05 | Расчёт по опубликованной странице | После BE-04 |
| BE-06 | Поиск курсов в редакторе на демонстрационных данных | Готова к выдаче |
| BE-07 | Поиск курсов из системы заказчика | После BE-06 и получения контракта API |

## BE-02. Список лендингов партнёра

Добавить `GET /api/landings?offset=0&limit=20` в группу редактора. Для карточки вернуть `id`, `slug`, имя и тип из черновика, `revision` и `publishedRevision`. Ответ содержит `items` и `total` для текущего партнёра. Сортировать по slug, чтобы порядок страниц был воспроизводим. Фронтенд сможет отличить черновик, опубликованную страницу и страницу с новыми правками по двум номерам ревизий.

**Приёмка.** Создать два лендинга от A и один от B. Запрос A возвращает только его две страницы. Для нового партнёра результат пуст. Без авторизации сервер возвращает 401. Две последовательные выборки с `limit=1` дают разные ID. Лимит вне 1–100 или отрицательный offset даёт 400. В ответе списка отсутствуют массивы блоков.

## BE-03. Предпросмотр черновика

Добавить `GET /api/landings/{id}/preview?segment=guest|member`. Запрос доступен владельцу, читает текущий черновик и возвращает формат блоков публичной страницы. Использовать существующее правило `DocumentRules.Visible` и сохранить порядок блоков. По умолчанию выбрать guest. Параметр выбора аудитории относится только к предпросмотру редактора.

**Приёмка.** У черновика с общим, скрытым и доступным участнику блоками гость видит первый, а участник — первый и третий. Скрытый блок отсутствует в обоих ответах. Предпросмотр работает до первой публикации. Сразу после правки владелец видит новый текст, а публичный маршрут возвращает прежнюю версию. Чужой ID даёт 404, неизвестный сегмент — 400.

## BE-04. Настройки блока калькулятора

Подключить результат BE-01 к структуре `Block.Props`. Разрешить тип `calculator` в схеме документа. Написать адаптер полей `min`, `max`, `step`, `default`, `pricePer` и массива `discounts`. Редактор может присылать число или строку с числом. Проверять диапазон, шаг, значение по умолчанию и пороги скидок при записи черновика. Общие правила цен использовать из BE-01.

**Приёмка.** Один и тот же корректный блок с числом 1400 и строкой «1400» сохраняется через POST и PUT. Для default = 17 при диапазоне 4–48 и шаге 4 API возвращает 400 с указанием блока и поля. При неудачном PUT сохранённый документ и его ревизия остаются прежними. Ранее поддержанные четыре типа блоков продолжают сохраняться.

## BE-05. Расчёт по опубликованным настройкам

Добавить `POST /api/public/landings/{slug}/blocks/{id}/calculate` с телом `{ "quantity": 16 }`. Найти калькулятор в активной публикации, проверить его видимость для текущего посетителя и передать сохранённые настройки в BE-01. Вернуть количество, сумму до скидки, процент, итог, цену занятия и валюту.

**Приёмка.** Для 16 занятий по 1 400 ₽ со скидкой 10% сервер возвращает 20 160 ₽ и 1 260 ₽ за занятие. Изменение цены в черновике влияет на публичный расчёт только после повторной публикации. Для скрытого или чужого сегменту блока, отсутствующей публикации и ID блока другого типа ответ 404. Количество вне допустимого шага даёт 400.

## BE-06. Поиск курсов для редактора

В модуле Catalog описать интерфейс поиска с идентификатором партнёра, текстом запроса и ограничением числа результатов. Подключить демонстрационную реализацию к `GET /api/catalog/courses?q=...&limit=20` с политикой `partner`. Возвращать `items` с полями `externalId` и `title`. Идентификатор партнёра получать из авторизации.

**Приёмка.** В демоданных есть два партнёра с разными курсами. Поиск находит курс по части названия без учёта регистра. Пустой запрос показывает доступные курсы в пределах лимита, отсутствие совпадений даёт пустой массив. Курс другого партнёра отсутствует даже при точном совпадении названия. В OpenAPI указан тип ответа. Фронтенд может использовать маршрут, пока команда ожидает доступ к реальному каталогу.

## BE-07. Адаптер каталога заказчика

Для начала нужны описание тестового API, пример успешного ответа, способ авторизации и правило доступа к курсам партнёра. Реализовать типизированный HTTP-клиент за интерфейсом BE-06. Адрес и параметры доступа передавать через конфигурацию, токен хранить в секретах окружения.

**Приёмка.** На тестовом окружении доступный курс появляется в том же формате, что и в BE-06. При тайм-ауте возвращается 504, при недоступности сервиса — 502. Ошибка сервиса отличается от успешного поиска без совпадений. В PR приложить пример обезличенного ответа и автоматические проверки преобразования данных и ошибок.
